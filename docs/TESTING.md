# 验证范围

## 自动检查

```bash
./.venv/bin/python -m unittest discover -s tests -v
./.venv/bin/python build_control_ui.py
./scripts/check_public_tree.py
```

Python 检查使用合成人脸特征和临时目录，主要覆盖：

- 本人不触发，其他人必须经过完整计时，不混用不同人的时间。
- 转头、丢失检测、摄像头卡顿清零；短眨眼暂停，长时间闭眼清零。
- 空闲低频、出现其他人后提高频率，出现本身不等于正在注视。
- 严格超过 5 秒后才生成截图；同一事件一张，疑似本人或眼神不明时跳过。
- 图片裁剪、元数据、文件权限、录入资料读写、单人模拟禁止真实保存。
- 摄像头断流后重新打开、停止进程时不误杀其他程序。
- 安装准备流程不注册或启动登录任务。

Swift 自检覆盖状态判断、初始化顺序、完整窗口布局和浅/深色外观的白字绘制。它不启用摄像头，不把应用内渲染图当作屏幕最终颜色的证明。

## 人工验收

1. 先停止后台，再录入本人，预览中确认本人稳定显示为 `YOU`。
2. 用 `watch --simulate-self` 检查连续 15 秒、转头清零和恢复计时。它不验证真实陌生人身份分类，也不保存图片。
3. 由另一人配合检查身份区分和注视判断，并在本地检查超过 5 秒生成的事件图片。身份误判和视线误判要分别记录。
4. 单独执行 `test-lock` 验证系统真的锁屏，再测试实际旁观者触发的完整链路。
5. 检查状态栏字色和菜单点击，以及停止后相机进程、自启和系统任务均已结束。
6. 如需验证自动恢复，可在受控条件下终止自己的工作进程，检查新进程和更新后的心跳；这不等同于长时间稳定性验收。

此前在一台 Apple Silicon Mac 上完成过本人录入、本人预览、单人模拟、单独锁屏和进程恢复测试。没有系统性的真实多人准确率、误报率或功耗测量，不据此宣称安全或识别性能达标。
